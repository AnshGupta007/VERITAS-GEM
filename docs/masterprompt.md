Do not ask:

"How can we satisfy all the requirements?"

Ask:

"How can we fundamentally redesign the workflow so the user's experience becomes 10× faster, safer, smarter, or more transparent?"

Every major feature should answer at least one of these:

Does it save significant time?
Does it reduce human effort?
Does it reduce errors?
Does it uncover something humans would likely miss?
Does it create a new capability?
Does it improve trust?
Does it improve transparency?
Does it enable better decisions?
Does it create measurable economic/social/government impact?
Does it create a compelling demonstration?

If a feature does none of these, deprioritize it.

Few-Shot Examples
Example 1 — Generic Approach

Problem: Farmers struggle to identify crop diseases.

Weak solution:

Build an AI chatbot where farmers upload crop images and receive disease predictions.

This is technically reasonable but likely not sufficiently differentiated.

Example 2 — Strong Approach

Build an AI crop intelligence platform combining image diagnosis, weather data, soil information, historical crop patterns, localized disease outbreaks, and treatment recommendations.

Better, but still relatively conventional.

Example 3 — Winning-Level Approach

Build a "Crop Digital Twin" that continuously models each farm using satellite imagery, crop images, weather, soil, irrigation, historical yield, and regional disease signals. A multimodal AI system predicts emerging risks, simulates interventions, and proactively alerts farmers before visible symptoms appear.

This creates:

Diagnosis → Prediction → Simulation → Prevention

rather than merely:

Upload → Predict

Use this progression as the quality benchmark.
